Who lands here, and why it is not a refusal ------------------------------------------- SEB for macOS/iOS 3.0+ runs on WKWebView, which cannot attach the Config Key to an HTTP request at all — the project's own documentation says it never will, and the way in for those clients is the Safe Exam Browser JavaScript API. So a gated paper opened by an iPad reaches this page *first*: the script below asks the client's own API for `SafeExamBrowser.security.configKey`, sends it to `/student/exams//seb-claim`, and only then opens the exam. The value it sends is the same value the header would have carried, which is why the server verifies it with the same comparison and why there is no second verification here to keep in step with the first. Why the states are rendered rather than written by the script ------------------------------------------------------------ Every message on this page is a `t()` pair bound to `state`, so the language toggle keeps working and no copy is assembled — and frozen — inside JavaScript. The script only ever sets a *word* (`checking` / `refused` / `error`); the words a pupil reads come from the template. #} {% block content %}
