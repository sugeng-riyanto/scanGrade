{# ── The three views of the same marks ────────────────────────────────────────── Rendered by both student pages (dashboard + results) from this one file, and drawn by one factory — `window.sgVisualSummary`. Two implementations of "the same three charts" is how the two pages would start printing different distributions of the same marks, which is the defect this repository keeps paying for. Nothing here reads the host component's own rows: the points arrive as JSON built by the route (`_chart_points`) in *one shape for both pages*, already blanked for any mark the teacher has not released. That is also why the switch here is the `showScores` both pages already carry: a chart is a loud way to print the score the table masks, and a switch that hid the table while the axis printed every mark is a switch that does not work. Four things this file deliberately does **not** own: * the theme's text and grid colours — one reader in `base.html` sets `Chart.defaults` from the same CSS tokens everything else uses, so a chart cannot invent a palette the rest of the app does not have; * the point data — the route builds it, once, for both pages; * the `t()` copy — the host page's `t` is the same pair table the rest of it uses; * the switch — `showScores` is the host's own. What it does own: the *data* colours (the band ramp), the hover, and the redraw. The last two exist because of the pie. Chart.js resizes and re-themes its own canvases; a canvas painted by hand gets neither for free, so the pie was stale after every rotate and silent under the cursor, which on a phone is the only way to read a slice. #}

{# One column on a phone, two on a tablet, three only where a column is wide enough to hold an axis — `lg` is where this page's sidebar appears, so three columns at 1024 would leave each chart about 220px, narrower than the phone's single one. `md`/`xl` are the widths a chart can actually be read at. #}

{# A canvas needs a parent with a height: `maintainAspectRatio: false` with an unsized one makes the canvas grow on every resize. #} {# `w-full h-full` on the canvases Chart.js manages, so the layout is right *before* Chart.js writes its own inline size — which is when `_small()` is answered. `h-full` is not enough for the hand-drawn pie: measured, the pie's own height attribute drove its layout, so every redraw grew it (a 224px holder, a 1665px canvas, and a card as tall as the page). That one is sized from its holder instead. #}

{# The one canvas Chart.js does not own: `hoverSlice` is set by the pointer *and* by the legend below, and `_pieCtx` sizes it. It carries **no** `:style` binding on purpose. An Alpine string style rewrites the whole style attribute, which wipes the inline size `_pieCtx` set — measured, the canvas then rendered at its attribute size (2x its css size on a phone) and left its card the moment it was hovered. The cursor is set by `drawPie3D`, where the hover state lives. #}
